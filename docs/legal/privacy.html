Política de Privacidad de TokVision

Última actualización: 4 de noviembre de 2026

TokVision es una aplicación cliente para Android TV / Google TV que, en su alcance actual, permite iniciar y cerrar sesión con una cuenta propia de TikTok mediante Login Kit (OAuth 2.0 + PKCE). La Display API, los perfiles, los vídeos, los favoritos y el historial todavía no están implementados. Esta política describe el comportamiento comprobado en el código actual, no funciones futuras del roadmap.

1. Datos que procesa la versión actual

DatoOrigenUso y persistencia
state y code_verifier de PKCE Generados por TokVision para cada intento de login Validan el callback OAuth. Permanecen en memoria durante el intento y se descartan al completar o cancelar; no se guardan en disco.
Código de autorización Callback de TikTok dentro del WebView Se intercambia con TikTok junto con el code_verifier; no se conserva como historial local.
open_id Respuesta del endpoint OAuth de TikTok Identifica localmente la cuenta conectada. Se almacena cifrado en el dispositivo; no se consulta el perfil.
access_token, refresh_token y expiración Respuesta del endpoint OAuth de TikTok Se almacenan cifrados para mantener la sesión. La rutina de renovación está preparada en la capa de autenticación, pero todavía no hay una función de Display API que la invoque.
Contraseña de TikTok La introduce el usuario en la página oficial de TikTok TokVision no la lee ni la almacena; la autenticación ocurre en el WebView de TikTok.
Nombre, avatar, biografía y vídeos propios No se obtienen en la versión actual No se consultan ni almacenan. No se solicita el scope video.list.
Favoritos e historial de reproducción Funcionalidad no implementada No existe una base de datos local para esos datos y no se guardan.

La autorización solicita únicamente el scope user.info.basic. La versión actual no llama a /v2/user/info/, /v2/video/list/ ni /v2/video/query/. Tampoco solicita seguidores/seguidos, mensajes privados ni contenido de otras cuentas. Los valores de calidad y reproducción visibles en Ajustes son placeholders, no preferencias persistidas.

2. Dónde se almacenan los datos

  • open_id, access token, refresh token y expiración se guardan en EncryptedSharedPreferences, con una clave maestra respaldada por Android Keystore.
  • El estado PKCE (state y code_verifier) y el código de autorización viven solo durante el flujo de login; no se persisten como historial.
  • El archivo privado de estado de sesión contiene únicamente una marca booleana de invalidación, no tokens ni identificadores.
  • El manifiesto de Android desactiva el backup de datos de la aplicación (allowBackup=false).
  • TokVision no tiene servidor propio, backend ni base de datos remota controlada por sus desarrolladores.

La pantalla de autorización se abre en un WebView de Android. TikTok puede mantener cookies y almacenamiento web propios en ese WebView. TokVision no lee esas cookies ni las elimina explícitamente al cerrar sesión; pueden permanecer en el dispositivo hasta que se borren los datos de la aplicación.

3. Destinos de red y transferencias

  • https://www.tiktok.com/v2/auth/authorize/: página oficial de autorización que se abre en el WebView. TikTok puede cargar recursos adicionales de sus propios dominios durante ese proceso.
  • https://open.tiktokapis.com/v2/oauth/token/: endpoint OAuth al que el cliente HTTP envía el código de autorización y el verificador PKCE para el intercambio; el flujo de renovación, cuando sea invocado, envía el refresh token.

En el intercambio OAuth actual también se envían el client key, el redirect URI y el client secret configurado para el build. TikTok recibe esos datos y puede procesar la dirección IP, datos técnicos de conexión, cookies y otra información de la sesión de autorización conforme a sus propias políticas. Consulta las políticas de TikTok para conocer ese tratamiento.

La versión actual no llama a la Display API, no consulta perfiles o vídeos y no envía datos a un backend de TokVision. No se identificó otro destino de API de la aplicación en el código revisado.

4. Registros, analítica y diagnósticos

La revisión del código fuente y de las dependencias declaradas no identificó SDK de publicidad, analítica, telemetría ni reporte de fallos de terceros. Tampoco se encontraron llamadas de logging de la aplicación que impriman tokens, refresh tokens, códigos OAuth o el client secret. Los errores de autenticación se presentan al usuario mediante mensajes genéricos; no se envían a un servidor de TokVision.

Android/Google y TikTok pueden generar o procesar diagnósticos y datos técnicos bajo sus propias políticas. Esta declaración describe únicamente el comportamiento de la aplicación y las dependencias revisadas; no controla los registros del sistema operativo ni los servicios de TikTok.

5. Retención, cierre de sesión y eliminación

Los tokens y el open_id permanecen cifrados en el dispositivo mientras la sesión local exista. Puedes cerrar sesión desde Ajustes → Cuenta → Cerrar sesión; TokVision invalida la sesión local e intenta eliminar el almacenamiento cifrado. Si el almacenamiento falla, conserva una marca local de invalidación para evitar restaurar una sesión rechazada.

El cierre de sesión local no revoca por sí solo el permiso concedido en los servidores de TikTok y no elimina explícitamente las cookies o el almacenamiento web del WebView. Para revocar el acceso, utiliza la configuración de tu cuenta de TikTok → Seguridad y privacidad → Aplicaciones y sitios web conectados. Para eliminar también los datos locales y cookies del WebView, borra los datos de TokVision desde los ajustes de Android o desinstala la aplicación. TokVision no ofrece eliminación de la cuenta de TikTok.

Como los favoritos y el historial todavía no están implementados, esta versión no tiene esos registros que borrar. No existe una copia de esos datos en servidores de TokVision.

6. Límite de seguridad del intercambio OAuth

El código actual realiza el intercambio OAuth desde el dispositivo Android. El TIKTOK_CLIENT_SECRET configurado localmente se incorpora a BuildConfig y se envía desde la aplicación al endpoint de tokens. Cualquier secreto incluido en un APK de Android puede extraerse; guardarlo en un archivo local ignorado por Git, minificar u ofuscar el APK no lo convierte en un secreto seguro.

Por ese motivo, no distribuyas APKs de desarrollo ni builds que contengan un client secret real. PKCE protege el flujo frente a la interceptación del código de autorización, pero no vuelve confidencial un secreto empaquetado en un cliente público. La arquitectura apta para distribución requiere un backend/token broker HTTPS que realice el intercambio y mantenga el client secret y los refresh tokens del lado servidor. Ese backend todavía no existe; el login no debe considerarse listo para una distribución pública hasta que se implemente y acepte esa arquitectura.

7. Menores de edad

TokVision no está dirigido a menores de edad y no recopila deliberadamente información de menores. El uso requiere una cuenta de TikTok existente, sujeta a los requisitos de edad y términos de TikTok.

8. Cambios a esta política

Si cambia el comportamiento de la aplicación o los datos que procesa, esta política se actualizará en la misma URL. Las funciones futuras no se consideran disponibles hasta que estén implementadas y verificadas.

9. Contacto

Este proyecto es de código abierto. Consulta el repositorio en github.com/vampirekun/TokVision para reportar problemas o dudas sobre privacidad.
